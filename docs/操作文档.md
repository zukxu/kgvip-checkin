# kgcheckin-py 操作文档与启动说明

> 本文档对应仓库**当前代码**：由 Node.js 版 [kgcheckin](https://github.com/develop202/kgcheckin) 的 `main.js` 转换而来的 Python 版本。
> README.md 中描述的 `kugou/` 直连酷狗 API 架构为后续规划，尚未实现；当前版本仍依赖本地 Node api 服务转发请求。

---

## 1. 架构与模块说明

```
USERINFO 环境变量（JSON 账号列表）
        │
        ▼
   main.py ──签到流程──► service.py ──启动子进程──► npm run apiService
                          （HTTP 请求）              （api/ 目录，Node 服务）
                              │                          │
                              ▼                          ▼
                       127.0.0.1:3000  ──────────►  酷狗 API
```

签到时若 token 发生续期，经 `github_secrets.py` 调用 `gh` CLI 回写仓库 Secret `USERINFO`。

| 文件 | 来源（Node.js 版） | 职责 |
|------|-------------------|------|
| `main.py` | `main.js` | 主入口：自动检测登录状态（未登录先引导登录），签到流程：听歌领 VIP、看广告领 VIP（每日 8 次）、查 VIP 到期时间、每日 token 续期 |
| `login.py` | `qrcodeLogin.js` / `phoneLogin.js` / `sent.js` | 扫码登录、手机号验证码登录 |
| `service.py` | `utils/utils.js` | 启动/关闭 Node api 服务、发送 HTTP 请求、延时 |
| `safe_log.py` | `utils/safeLog.js` | 日志脱敏（昵称、userid、token、手机号）、响应摘要 |
| `github_secrets.py` | `utils/githubSecrets.js` | 通过 gh CLI 写仓库 Secret |
| `color_out.py` | `utils/colorOut.js` | ANSI 彩色终端输出 |
| `api/`（已内置精简版） | 原项目 `api/` | KuGouMusicApi 本地服务（仅保留本项目所需 9 个接口），监听 `127.0.0.1:3000` |

## 2. 环境要求

| 依赖 | 版本 | 用途 |
|------|------|------|
| Python | 3.10+（推荐 3.11） | 运行签到脚本 |
| Node.js + npm | ≥ 18（api 服务要求 ≥ 12） | 运行本地 api 服务 |
| gh CLI | 任意近期版本 | 仅"自动刷新 token 回写 Secret"需要；本地纯签到可不装 |
| 网络端口 | 3000 空闲 | api 服务监听端口 |

## 3. 启动说明（本地运行）

### 3.1 首次准备（一次性，约 5 分钟）

仓库已内置根目录 `package.json` 与精简版 `api/`（9 个接口），clone 后只需安装依赖。

**第 1 步：安装 Node 依赖（约 1 分钟）**

```powershell
cd api
npm ci
cd ..
```

**第 2 步：安装 Python 依赖（约 30 秒）**

```powershell
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

（仓库已含 .venv 时可跳过创建，直接安装依赖。）

### 3.2 首次登录（无需手动配置 USERINFO）

**账号加载优先级**：环境变量 `USERINFO` → 本地 `userinfo.json` → 两者皆无时自动引导登录。

运行 `python main.py` 检测到未登录时，会交互式引导：

```
未检测到账号信息（环境变量 USERINFO 与本地 userinfo.json 均为空）
请选择登录方式: 1 扫码登录（推荐） / 2 手机号验证码登录  [1]:
```

**方式一：扫码登录（推荐）**——自动保存二维码图片并用系统查看器打开，酷狗 APP 扫码确认即可（约 2 分钟内完成，超时或过期可重跑）。

**方式二：手机号登录**——依次输入手机号 → 收到验证码后输入，即登录成功。

登录成功后：

- 账号自动保存到本地 `userinfo.json`（已被 .gitignore 排除，不会提交）
- 配置了 `PAT` 时自动同步到 GitHub Secret `USERINFO`（Actions 可直接使用）
- 本次运行**立即继续签到**，无需重新执行

命令行参数（也可跳过检测强制登录，用于追加账号）：

```powershell
.venv\Scripts\python.exe main.py             # 智能签到：未登录自动引导，已登录直接签到
.venv\Scripts\python.exe main.py --qrcode    # 强制扫码登录后签到
.venv\Scripts\python.exe main.py --login     # 手机号验证码登录后签到
.venv\Scripts\python.exe main.py --qrcode --count 3   # 一次扫码登录 3 个账号
```

多账号：重复运行 `--qrcode` 或 `--login` 即可追加；同一 userid 重复登录仅更新 token，不会产生重复账号。

> 手动配置 USERINFO 仍受支持（设环境变量即可，优先级最高），一般无需使用。

### 3.3 运行签到

必须在项目根目录执行：

```powershell
.venv\Scripts\python.exe main.py
```

首次运行会先引导登录（见 3.2），之后直接签到。正常输出示例：

```
账号 张三********丰 开始领取VIP...
开始听歌领取VIP...
听歌领取成功
开始领取VIP...
第1次领取成功
...
第8次领取成功
今天是：2026-09-07
VIP到期时间：2099-12-31
```

退出码：`0` 全部成功；出现领取异常时抛出 `RuntimeError`，退出码非 0（GitHub Actions 会标红便于察觉）。

## 4. GitHub Actions 自动签到

### 4.1 配置 Secrets（一次性，约 3 分钟）

仓库 `Settings → Secrets and variables → Actions` 新增：

| Secret | 必需 | 说明 |
|--------|------|------|
| `USERINFO` | 否 | 账号 JSON 数组；未配置时可在 Actions 手动 Run workflow 扫码登录自动写入（见下） |
| `PAT` | 建议配置 | 用于登录/每日 token 续期后回写 `USERINFO`；创建方式见 README「创建 PAT」一节，需授予 Secrets 读写权限 |

**首次登录（Actions 内）**：`main.yml` 已含 `workflow_dispatch` 手动触发。Secrets 未配置 `USERINFO` 时直接 `Run workflow`，脚本会走扫码登录并把二维码 data URI 打印到日志——拼接后在浏览器打开、扫码确认，配置了 `PAT` 即自动写入 `USERINFO`，之后每日定时任务正常自动签到。手机号登录则需在 workflow 中添加环境变量 `PHONE` 和 `CODE`（或使用本地登录）。

### 4.2 Workflow 文件

`.github/workflows/main.yml` 已内置仓库，内容如下（无需手动创建）：

```yaml
name: main
on:
  workflow_dispatch:
  schedule:
    - cron: '10 17 * * *'  # UTC 17:10 = 北京时间每天 01:10
permissions:
  contents: read
jobs:
  run:
    runs-on: ubuntu-latest
    steps:
      - name: 检出仓库
        uses: actions/checkout@v6
      - name: 创建 Python
        uses: actions/setup-python@v6
        with:
          python-version: '3.11'
          cache: 'pip'
      - name: 创建 Node
        uses: actions/setup-node@v6
        with:
          node-version: 24
          cache: 'npm'
          cache-dependency-path: ./api/package-lock.json
      - name: 🔧 检查GitHub CLI
        run: |
          if ! command -v gh >/dev/null 2>&1; then
            curl -fsSL https://cli.github.com/packages/githubcli-archive-keyring.gpg | sudo dd of=/usr/share/keyrings/githubcli-archive-keyring.gpg
            sudo chmod go+r /usr/share/keyrings/githubcli-archive-keyring.gpg
            echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null
            sudo apt update
            sudo apt install gh -y
          fi
          gh --version
      - name: 缓存 api node_modules
        id: cache-npm
        uses: actions/cache@v5
        with:
          path: ./api/node_modules
          key: ${{ runner.os }}-node-${{ hashFiles('./api/package-lock.json') }}
          restore-keys: |
            ${{ runner.os }}-node-
      - name: 安装 api 依赖
        run: cd api && npm ci
        if: ${{ steps.cache-npm.outputs.cache-hit != 'true' }}
      - name: 安装 Python 依赖
        run: pip install -r requirements.txt
      - name: 签到
        run: python main.py
        env:
          USERINFO: ${{ secrets.USERINFO }}
          PAT: ${{ secrets.PAT }}
          GITHUB_REPOSITORY: ${{ github.repository }}
```

配置后可在 Actions 页面 `Run workflow` 手动验证一次，之后每天北京时间 01:10 自动执行。

## 5. 环境变量一览

| 变量 | 必需 | 说明 |
|------|------|------|
| `USERINFO` | 否 | 账号 JSON 数组；优先级最高，一般由登录自动生成，无需手动设置 |
| `PAT` / `GH_TOKEN` | 否 | 写 Secret 的 token，两者任配一个即可（优先 `GH_TOKEN`） |
| `PHONE` / `CODE` | 否 | 手机号登录时免交互输入（Actions 场景）；本地运行会直接提示输入 |
| `GITHUB_REPOSITORY` | Actions 自动注入 | 仓库全名 `owner/repo`，写 Secret 时必须 |
| `ALLOW_PRINT_USERINFO` | 否 | 无 PAT 且需手动复制账号信息时设为 `true`/`1`/`yes`/`是`，默认关闭 |

## 6. 常见问题

| 现象 | 原因与解决 |
|------|-----------|
| `缺少 api 服务文件（package.json / api/ 目录）` | 仓库文件缺失：确认已完整 clone，`api/` 与 `package.json` 均已内置 |
| `api 服务启动超时（http://127.0.0.1:3000 无法访问）` | 先手动 `cd api && npm run start` 看报错；缺依赖执行 `npm ci`；确需更长时间可调大 `service.py` 的 `SERVICE_READY_TIMEOUT_SECONDS`（默认 30 秒） |
| `Connection refused` / 请求全部失败 | api 服务中途退出：确认 3000 端口未被占用，查看 `api/` 是否完整 |
| `未找到 npm` | 未安装 Node.js 或不在 PATH，安装后重开终端 |
| Windows 控制台中文乱码 | 执行 `chcp 65001`，或设置 `$env:PYTHONUTF8 = "1"` 后再运行 |
| 二维码图片未自动打开 | 手动打开项目根目录的 `login_qrcode.png` 扫码 |
| `二维码已过期` / `等待超时` | 重新运行即可获取新二维码 |
| `token过期或账号不存在` | token 失效：删除 `userinfo.json` 后重跑自动引导登录，或 `python main.py --qrcode` 直接重新登录 |
| `暂不支持多账号绑定手机登录` | 酷狗限制：该手机号绑定了多个账号，请改用扫码登录 |
| `PAT/GH_TOKEN 未配置，无法同步 GitHub Secret` | 仅警告不影响签到；配置 PAT 后 token 续期时自动回写 |
| `今日已领取` / `今天次数已用光` | 正常提示：今日已完成 / 广告次数用完，非错误 |
| VIP 到期时间只有两天 | 正常：青春 VIP 按小时累加，听歌 +24h、广告每次 +3h（8 次共 +24h），每日上限 48h；每天签到到期时间持续顺延，断签才真正到期 |
| 端口 3000 被占用 | 修改 `api/.env` 中端口，并同步修改 `service.py` 的 `API_BASE_URL` |
| 想更换/清空账号 | 删除根目录 `userinfo.json`（同时更新 GitHub Secret `USERINFO` 可在仓库设置中删除） |

> **安全提示**：`userinfo.json` 与 `login_qrcode.png` 含登录凭据，已被 .gitignore 排除，切勿手动提交或分享。

## 7. 与 Node.js 版的行为差异

- 签到流程、错误码判断（`130012` 今日已领取、`30002` 次数用光）与原版一致。
- **token 续期为每天调用**（原版仅周日）：`/login/token` 是幂等的 token 重登录接口，未到期时服务端返回原 token，无副作用；token 变化才回写本地文件与 Secret。
- 登录已集成进 `main.py`（原版为独立的 `qrcodeLogin.js` / `phoneLogin.js` / `sent.js` 脚本）：未登录自动引导，登录后直接签到。
- 账号信息除 GitHub Secret 外，同时保存到本地 `userinfo.json`，便于本地免配置运行（原版仅依赖 Secret）。
- 原版 `APPEND_USER=是` 才合并账号，Python 版默认按 userid 合并（重复登录仅更新 token）。
- 扫码登录本地运行时自动保存并打开二维码图片（原版仅打印 base64）；Actions 中仍打印 data URI 到日志。
- 省略了原版末尾 `process.exit(0)`：Python 脚本正常结束即退出码 0，异常时非 0。
- 日志脱敏规则与原版一致（昵称保留首尾、userid 保留首尾片段、敏感字段 `[REDACTED]`、手机号/GitHub token 正则脱敏）。
